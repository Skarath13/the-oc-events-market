# Structured-data map

Schema is generated by `src/lib/seo.ts`, uses stable entity IDs, and must remain consistent with
visible content.

| Route family                                                                                 | JSON-LD                                                                                  |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Home                                                                                         | `Organization`, `WebSite`                                                                |
| Services index                                                                               | `BreadcrumbList`                                                                         |
| Verified package page                                                                        | `Service`, `BreadcrumbList`                                                              |
| Event-type page                                                                              | `Service`, `BreadcrumbList`                                                              |
| About, trusted network, celebrations index, journal index, contact, vendor page, legal pages | `BreadcrumbList` where a meaningful hierarchy exists                                     |
| Future celebration story                                                                     | `BreadcrumbList`; add `ImageObject` only for approved project media                      |
| Future journal article                                                                       | `BlogPosting`/`Article` plus `BreadcrumbList` only after verified author and dates exist |

`Organization` is used rather than `LocalBusiness` while public contact/address/hours are unverified.
Do not add `Person`, `Review`, `AggregateRating`, `Offer`, price data, or `Event` schema without
matching verified visible content. Visible FAQs are intentionally not marked up as FAQ structured
data; the site does not depend on a FAQ rich result.

Validation before launch:

1. Inspect every emitted `application/ld+json` block and parse it as JSON.
2. Run Schema.org Validator on representative pages.
3. Run Google Rich Results Test only for supported eligible types.
4. Confirm entity URLs and `@id` values use the final canonical domain.
5. Recheck after any feature flag, address, team, portfolio, or journal change.
